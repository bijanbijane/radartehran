## 3. Section 23 — Required Agent Report for Architecture Decisions Impacted by `WS-A1`

### Decision Report: `ADR-0004` (Evidence Provenance, Verification State & Data Freshness) & `ADR-0008` (KPI Definitions & Metric Governance)
1. **Decision ID and Title:** `ADR-0004` — Evidence provenance, verification state, and data freshness; `ADR-0008` — KPI definitions and analytics governance.
2. **Current Status:** `PROPOSED` (Implementation attempted in `WS-A1`, currently exhibiting unapproved architectural drift due to `F-A1V-03`, `F-A1V-04`, `F-A1V-07`, and `F-A1V-08`).
3. **Triggering Problem:** Neighborhood market metrics in `src/data/realMarketPriceAggregator.ts` previously blended Mulberry32 PRNG synthetic listings with observed secondary-market asking prices, conflated statistical outliers with fraud counts, and presented asking-price adjustments as closing transaction prices.
4. **Repository Evidence (`E1`, `E2`):**
   - `src/data/realMarketPriceAggregator.ts:260-275` still runs `seededRandom(hoodId * 997 + Math.floor(Date.now() / 86_400_000))` when `observedEvaluated.length < 3`, returning `sampleCount: 12`, `validSampleCount: 12`, `confidenceScore: 74` (`> 71` for 3 real samples), and synthetic `iqrLowPerSqm`/`iqrHighPerSqm`.
   - `src/components/views/ProductIntelligenceView.tsx:47, 231` and `src/components/CompareModal.tsx:8` pass hardcoded `[]` to `aggregateNeighborhoodMarketMetrics`, erasing `hood.bargains`.
   - `docs/adr-evolution-and-governance.md` and `docs/architecture/ARCHITECTURE-DECISIONS.md` have conflicting ADR numbering (`ADR-004`..`ADR-007` used for two different sets of decisions).
5. **Product Principle Affected:** Epistemic honesty, calibrated user reliance, separation of observed evidence from model/synthetic estimates, and non-deceptive metric definitions.
6. **Options Considered:**
   - **Option A (Current Defective Hybrid in `realMarketPriceAggregator.ts`):** Keep `syntheticRaw` (12 PRNG rows) inside `evaluated` when `N < 3` so legacy fields (`iqrLowPerSqm`, `sampleCount: 12`, `confidenceScore: 74`) remain populated with numbers, while adding new fields (`observedSampleCount: 0`, `evidenceIndexScore: 0`, `observedIqrLowPerSqm: null`). *Rejected by `WS-A1-V` audit because UI components (`NeighborhoodInspectorTabs.tsx:201`, `ProductIntelligenceView.tsx:182`) still bind to the synthetic-contaminated `iqrLowPerSqm`/`iqrHighPerSqm` and `confidenceScore: 74` violates Missing-Data Transparency.*
   - **Option B (Recommended Strict Epistemic Separation):** Eliminate `syntheticRaw` generation from `aggregateNeighborhoodMarketMetrics` when `observedEvaluated.length < 3`. Set `sampleCount = observedEvaluated.length`, `validSampleCount = eligibleObservedCount`, `confidenceScore = evidenceIndexScore`, and return `null` (or explicit baseline-only reference without PRNG noise) for `iqrLowPerSqm`/`iqrHighPerSqm` when `eligibleObservedCount < 3`. Pass mapped `hood.bargains` consistently across all views (`NeighborhoodInspectorDrawer`, `ProductIntelligenceView`, `CompareModal`).
7. **Recommendation:** Adopt **Option B** in the authorized `WS-A1` remediation pass.
8. **Trade-offs:** Option B requires UI components (`NeighborhoodInspectorTabs.tsx`, `ProductIntelligenceView.tsx`) to handle `null` IQR bounds gracefully when `N < 3` (rendering an explicit `"نیازمند حداقل ۳ نمونه مشاهده‌شده"` badge rather than a numeric bar), trading visual numeric density for genuine epistemic honesty.
9. **Security and Privacy Impact:** None (operates on public/secondary listing aggregates; preserves existing PII protections).
10. **Data and Migration Impact:** Purely in-memory aggregation contract refinement; zero destructive database migrations required.
11. **UX and Human-Agency Impact:** Eliminates contradictory sample counts across panels (`2` vs `0`), removes false-precision synthetic IQR bounds, and replaces authoritative closing-transaction wording (`تخمین قیمت قطعی معاملات`) with transparent negotiation-scenario framing.
12. **Required Human Approval:** Human Product Owner / Technical Authority sign-off is required to accept `ADR-0004` / `ADR-0008` remediation and before any transition to `WS-B` (`WP-3` / `ADR-0005`).
13. **Verification Plan:** Execute the 4 Given/When/Then test scenarios defined in `docs/engineering/WS-A1-V/WS-A1-V-ACCEPTANCE-MATRIX-AND-TEST-PLAN.md` (Section 3).
14. **Related ADRs and Requirements:** `ADR-0004`, `ADR-0008`, `Legacy ADR-002`, `RADAR-DATA-001`, `RADAR-DATA-002`, `RADAR-DOM-003`, `RADAR-FUNC-009`, `RADAR-EPI-001`, `RADAR-EPI-002`, `RADAR-EPI-003`.
