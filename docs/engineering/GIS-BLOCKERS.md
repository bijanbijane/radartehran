1. **No usable execution runner in this session.** The authorized Desktop Commander MacBook is offline. The current PR head returned zero workflow runs and zero status checks when inspected. Repository issue [#49](https://github.com/bijanbijane/radartehran/issues/49) documents hosted GitHub Actions jobs failing before runner assignment across the project. GIS tests, typecheck and builds remain unverified on the current head.
2. **Canonical geography provider integration.** The NIPS/profile boundary contract requires an IRNI-owned, version-pinned, read-only geography provider. The intended Worker Service Binding is not verified as deployed/configured for the Radar API.
3. **NIPS durable storage is absent.** The connected Cloudflare inventory contains `radar-neighborhood-db`, `radar-user-db` and `radar-researcher-db`, but no `radar-profile-db`. Read-only schema inspection found no `nips_*` tables in any of the three Radar databases. The NIPS module defines contracts and validation only; it has no repository, migration, binding or write path. The NIPS ERD proposes a dedicated `radar-profile-db` shared by the independent IRNI and Radar NIPS backends, separate from the three existing databases. Its owner/writer policy and provisioning require a separate architecture decision; do not create NIPS tables in IRNI's `geo_*` database.
4. **D1 RTree capability is unverified.** Read-only probes confirmed basic SELECT, JSON and math functions. The Cloudflare D1 REST query surface denied `PRAGMA module_list` and `EXPLAIN CREATE VIRTUAL TABLE ... USING rtree` with `SQLITE_AUTH`; no existing virtual tables were found in `radar-neighborhood-db`. Do not infer RTree runtime support from the D1 export changelog. A non-production Worker-binding compatibility test is required.
5. **Authoritative data and licensing.** Production boundary and POI datasets, source references, licenses, retrieval dates and CRS metadata have not been assembled and verified by this work package.
6. **Topology validation is incomplete.** Strict interior-ring containment and hole-to-hole overlap/nesting checks are implemented with tests, but tests are unexecuted and MultiPolygon component overlap/intersection remains open. Segment intersection handling also needs explicit tests for endpoint-touching and collinear overlap cases.
7. **Active-boundary integrity.** Duplicate ACTIVE versions now fail closed in point resolution and profile boundary reads, but historical duplicates are not automatically repaired. Durable snapshot validation, mutation/hydration paths and all other consumers still need a complete integrity audit.
8. **CRS and metric calculations.** A verified local projected CRS and source-specific transformation policy have not been established. Do not guess a Tehran EPSG code or treat degrees as meters.

No production deployment, remote migration, live binding change, secret change, database creation, production data replacement or paid service activation was performed.
