## 1. Governance Principles & Status Definitions

Every Cloudflare capability is evaluated against 11 mandatory governance questions (real requirement solved, existing solution status, measurable advantage, account/plan/geographic eligibility, runtime compatibility, limits/failure modes, cost, state ownership, replacement difficulty, and immediate justification).

- **Statuses Used**:
  - `DISCOVERED`: Official product capability catalogued.
  - `RELEVANCE ASSESSED`: Evaluated against Radar Tehran's actual workload.
  - `NOT CURRENTLY NEEDED`: Workload does not justify adoption now.
  - `ARCHITECTURAL PREPARATION COMPLETE`: Clean adapter/contract boundary exists in source.
  - `IMPLEMENTED IN SOURCE`: Adapter/configuration code is implemented and unit-tested in repository.
  - `BLOCKED`: Requires external Cloudflare account credentials, domain delegation, or regional payment eligibility not available in the sandbox.
